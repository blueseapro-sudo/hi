## 1. 문제: 챗봇은 답만 준다 → 에이전트

| 구분 | 챗봇 | 에이전트 |
|---|---|---|
| 입력 | 질문 | 목표 |
| 동작 | 1회 응답 | 계획 → 도구 실행 → 결과 확인 반복 |
| 도구 | 없음 | 파일, 터미널, 웹, 외부 서비스 |
| 결과물 | 텍스트 | 파일, 실행된 작업 |

**에이전트 루프**: 목표 → 계획 → 도구 호출 → 관찰 → 수정 → 완료. 오늘 쓰는 도구는 **Claude Code**(터미널·데스크톱에서 일하는 Claude 에이전트)입니다.

> [!example] 바로 해 보기: 설치와 첫 실행
> 1. 터미널을 열고 아래를 입력합니다.
> ```bash
> npm install -g @anthropic-ai/claude-code
> mkdir agent-lab && cd agent-lab
> git init
> claude
> ```
> 2. 첫 지시: `이 폴더에 README.md를 만들고 프로젝트 목적을 "업무 자동화 실습"으로 적어줘`
> 3. 에이전트가 파일을 쓰기 전에 **허락을 묻는 장면**을 확인합니다.
> 성공 확인: README.md가 생기면 성공.
>
> 설치 방법은 바뀔 수 있으니 강의 전 [공식 문서](https://docs.claude.com)에서 확인합니다.

## 2. 문제: 매번 규칙을 설명해야 한다 → CLAUDE.md

**CLAUDE.md**는 에이전트가 시작할 때마다 읽는 업무 수첩입니다. 세션에서 `/init`을 실행하면 초안이 생깁니다.

```markdown
# 프로젝트 규칙
- 언어: 한국어, 문서는 간결체
- 산출물은 output/ 폴더에 저장
- 원본 데이터(data/)는 절대 수정 금지
- 작업 완료 후 변경 파일 목록을 보고할 것

# 자주 쓰는 명령
- 테스트: python -m pytest
```

| 위치 | 적용 범위 | 용도 |
|---|---|---|
| `~/.claude/CLAUDE.md` | 내 모든 프로젝트 | 개인 선호 |
| `./CLAUDE.md` | 이 프로젝트, Git으로 팀 공유 | 팀 규칙 |
| `./CLAUDE.local.md` | 이 프로젝트, 나만 | 개인 설정 |

> [!example] 생활 속 비유
> 지니에게 매번 "우리 부서는 이렇게 일해"라고 설명하는 대신, 램프에 업무 수첩을 붙여 둡니다.

## 3. 문제: 위험한 일까지 한다 → 권한 설정

`.claude/settings.json`에 허용·차단 명령을 적어 팀이 공유합니다.

```json
{
  "permissions": {
    "allow": ["Read", "Bash(python:*)", "Bash(git status)"],
    "deny": ["Bash(rm -rf:*)", "Read(./.env)"]
  }
}
```

**협업 원칙**: 사람은 목표 설정과 검토, 에이전트는 실행과 초안. 에이전트 작업은 Git 브랜치에서 하고 사람이 확인한 뒤 합칩니다.

## 4. 문제: 결과가 엉뚱하다 → 지시 설계 4요소

| 요소 | 나쁜 예 | 좋은 예 |
|---|---|---|
| 목표 | 보고서 만들어줘 | 월별 집행률 보고서 1쪽 |
| 맥락 | (없음) | data/budget.xlsx, 과장 결재용 |
| 제약 | (없음) | 표 1개, 300자 이내, 원본 수정 금지 |
| 완료 기준 | (없음) | 합계가 원본과 일치하는지 검증 후 보고 |

> [!example] 바로 해 보기: 나쁜 지시와 좋은 지시
> 1. 실습 폴더에 들어 있는 `data/budget.xlsx`(가짜 예산 5개 항목)를 씁니다.
> 2. "보고서 만들어줘"를 실행하고 결과를 저장합니다.
> 3. `/clear` 후 위 표의 좋은 예 네 줄을 그대로 실행합니다.
> 성공 확인: 두 번째 결과가 검증 결과까지 보고하면 성공.

> [!persona-field] 내 상황 예시: 현장 대원
> - 목표: 이번 달 출동 일지 요약 1쪽
> - 맥락: data/출동일지.xlsx(가짜), 센터장 보고용
> - 제약: 표 1개, 개인정보 열은 쓰지 않기, 원본 수정 금지
> - 완료 기준: 출동 건수 합계가 원본과 같은지 확인 후 보고

> [!persona-admin] 내 상황 예시: 행정·사무
> - 목표: 세부사업별 집행률 보고서 1쪽
> - 맥락: data/budget.xlsx, 과장 결재용, 단위 천원
> - 제약: 표 1개, 본문 300자 이내, 원본 수정 금지
> - 완료 기준: 예산액·집행액 합계가 원본과 같은지 확인 후 보고

> [!persona-prev] 내 상황 예시: 예방·안전
> - 목표: 이번 분기 자체점검 미제출 대상 목록
> - 맥락: data/점검대상.xlsx(가짜), 안내문 발송용
> - 제약: 대상물 이름과 기한만, 연락처 열은 쓰지 않기
> - 완료 기준: 전체 대상 수 = 제출 + 미제출인지 확인

> [!persona-general] 내 상황 예시: 처음 배우는 분
> - 목표: 다음 주 가족 일정표 1장
> - 맥락: 가족 4명, 평일 저녁과 주말만
> - 제약: 표 1개, 겹치는 일정은 빨간 글씨 대신 별표
> - 완료 기준: 빠진 요일이 없는지 확인

## 5. 문제: 큰일을 잘못된 방향으로 진행한다 → 계획 모드

- `Shift+Tab`으로 **계획 모드(Plan mode)** 로 바꾸면 에이전트가 실행 전에 계획만 보여 줍니다.
- 사람이 계획을 승인한 뒤 실행합니다. 원칙: **되돌리기 어려운 작업일수록 계획부터.**

## 6. 문제: 대화가 길어지면 흐려진다 → 컨텍스트 관리

| 명령 | 기능 | 쓰는 때 |
|---|---|---|
| `/clear` | 대화 초기화 | 주제가 바뀔 때 |
| `/compact` | 대화를 요약해 압축 | 대화가 길어질 때 |
| `@파일명` | 특정 파일만 지정 | 범위를 좁힐 때 |
| `/resume` | 이전 세션 이어가기 | 다음 날 이어서 할 때 |

> [!example] 생활 속 비유
> 컨텍스트는 작업대입니다. 필요한 서류만 올려 두면 실수가 줄어듭니다.

## 정리

### 1분 요약

에이전트는 목표를 받아 일을 끝낸다. CLAUDE.md로 규칙을, settings.json으로 권한을 주고, 목표·맥락·제약·완료 기준으로 지시하고, 큰일은 계획부터, 작업대는 깨끗하게.

### 문제 → 해결책 짝 맞추기

| 문제 | 해결책 |
|---|---|
| 답만 주고 일은 안 한다 | 에이전트 (Claude Code) |
| 매번 규칙 설명 | CLAUDE.md |
| 위험한 명령 실행 | 권한 설정 (allow / deny) |
| 엉뚱한 결과 | 지시 4요소 |
| 잘못된 방향의 대량 작업 | 계획 모드 |
| 긴 대화로 정확도 저하 | /clear, /compact, @파일 |

### 이 단계에서 쓰는 도구

- Claude Code, Git, 텍스트 편집기

### 셀프 체크

- [ ] 챗봇과 에이전트의 차이를 표로 말할 수 있다
- [ ] 내 프로젝트용 CLAUDE.md에 규칙 4줄을 썼다
- [ ] 지시 4요소로 지시문 1개를 썼다
- [ ] 계획 모드로 바꾸는 키를 안다

### AI에게 더 잘 요청하기

| 막연한 요청 | 용어를 넣은 요청 |
|---|---|
| 이 엑셀 정리해줘 | 계획 모드로 먼저 단계만 보여줘. 원본은 수정 금지, 결과는 output/에 |
| 다 고쳐줘 | 변경할 파일 목록과 이유를 먼저 보고하고, 내가 승인하면 진행해 |
